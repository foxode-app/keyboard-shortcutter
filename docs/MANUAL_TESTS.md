# macOS 実機テストチェックリスト

このチェックリストは自動テストで確認できない OS 統合の検証用です。未チェック項目は検証済みを意味しません。ローカル `.app` をビルドし、実際に権限を許可した上で実施してください。

## 起動と権限

- [ ] `/Applications` に配置して起動。Dock アイコンを常駐表示せず、メニューが開く。
- [ ] 通常モードで入力監視が未許可の状態では案内が表示され、クラッシュや管理者権限要求がない。
- [ ] 通常モードで入力監視を許可し、必要なら再起動すると監視開始できる。
- [ ] メニューの一時停止・再開が反映され、停止中はルールを実行しない。
- [ ] Fキーの割り当てがなく、Option の抑止がオフで入力ソース・アプリ・URL のルールだけなら、アクセシビリティを要求しない。
- [ ] ショートカット送信でアクセシビリティ未許可を説明し、許可後に動作する。
- [ ] 「Option（Alt）本来の動作を無効にする」をオンにし、アクセシビリティが必要な理由を案内する。アクセシビリティが未許可なら、監視中・抑止成功と表示せず開始失敗を示す。
- [ ] 抑止をオンにしてアクセシビリティを許可し、再開または再起動後に監視を開始できる。入力監視が未許可でも不要な許可要求をしない。アクセシビリティを取り消した場合も失敗状態と復旧手順を確認する。
- [ ] 抑止モードから通常モードへ戻したとき、入力監視が未許可なら案内を表示する。

## Option と修飾キー

- [ ] TextEdit 上で左 Alt（Option）単独押しを離すと ABC 英字入力に切り替わる。
- [ ] 右 Alt（Option）単独押しを離すと日本語のひらがな入力に切り替わる。日本語 IME のカタカナ・英数モードからも確認する。
- [ ] 左右 Option を数秒保持し、他の入力なしで離すと各 1 回実行する。
- [ ] Option + 文字、Option + 矢印、Option + マウスクリックでは単独押しが発火しない。
- [ ] Option を押したまま移動・ドラッグ・スクロールして離した場合の判定を確認する。
- [ ] 左右 Option を同時に押す、他の修飾キーを追加する、逆順で離す場合に誤発火しない。
- [ ] ルールを左右 Command / Control / Shift に変更して、左右それぞれを確認する。
- [ ] Caps Lock のオン・オフが Option 単独判定や通常ショートカットを妨げない。
- [ ] 内蔵キーボードと外付け JIS / ANSI / ISO キーボードで物理キーを確認する。

## Option 本来の動作の抑止

各項目を左右の Option で確認します。通常のモード変更はすべてのキーを離してから行い、入力ソースを ABC にした TextEdit などで比較してください。

- [ ] 抑止オフで Option + 矢印の単語移動や Option + E のアクセント入力が通常どおり働く。
- [ ] 抑止オンで Option 単独を押して離すと、左は ABC、右はひらがなへ切り替わる。長押しも各 1 回動作する。
- [ ] 抑止オンで Option + K は通常の K 入力、Option + 矢印は通常の矢印移動となり、Option + E ではアクセント入力待ちにならない。いずれも Option を離したとき入力ソースを切り替えない。
- [ ] Option + Command / Control / Shift の組み合わせで、Option 以外の修飾キーが維持される。キーを離した後に修飾状態が残らない。
- [ ] Option を押してクリック・ドラッグ・スクロールし、対応するアプリの Option 固有の動作（メニューの代替項目など）が働かない。マウス操作後に単独タップが発火しない。
- [ ] 左右 Option 同時押し、押す順・離す順の入れ替え、他の修飾キーとの併用で Option が漏れず、誤発火や解放後の状態残りもない。
- [ ] 登録した Control + Option + K のルールは抑止オンでも動作し、前面アプリには Control + K として届く。前面アプリと競合しない安全なアクションで確認する。
- [ ] 「ショートカット送信」で意図的に指定した Option を含む組み合わせは抑止オンでも Option 付きで届き、自己再帰しない。
- [ ] 一時停止中・終了後は通常の Option 動作に戻る。再開後は抑止が復帰する。
- [ ] 記録中は通常の Option が利用でき、Option を含むトリガーを記録できる。記録を終えると抑止が復帰する。
- [ ] 抑止設定のオン・オフが保存され、再起動で復元される。設定項目のない旧 JSON はオフで読み込み、既存ルールを維持する。
- [ ] Option を保持した状態での一時停止・再開、モード変更、記録開始・終了を個別に試し、誤った単独タップを実行しない。キーをすべて離した後に通常入力へ戻るか確認し、前面アプリに状態が残る場合は記録する。
- [ ] スリープ復帰・セッション復帰・イベントタップの無効化後に、復帰できた場合は抑止が再開する。失敗時は監視エラーを表示する。
- [ ] Secure Keyboard Entry などで抑止が効かない場合はその制限を記録し、保護された入力を終了した後に通常動作へ復帰する。ログイン画面や直接ハードウェア状態を読むアプリへの適用を前提としない。

- [ ] Control + Option + K と Command + Shift + Space のルールを作成できる。
- [ ] 音量・明るさ以外の操作は、長押しによるオートリピートでは 1 回のみ実行する。離して押し直すと再実行する。
- [ ] 修飾キーを余分に追加すると一致しない。
- [ ] Command + 左矢印などを一覧指定とキー記録の両方で作り、不要な Fn が付かず同じ組み合わせになる。
- [ ] Fn を実際に押したショートカットは、矢印や F キー固有のフラグと区別される。
- [ ] 抑止オフで元のキーが前面アプリにも届くこと、オンでは Option だけが取り除かれることを確認し、OS の割り当てと競合しない組み合わせを選ぶ。

- [ ] 片方を無効化すると有効なルールだけ実行する。
- [ ] アプリ起動で選択した `.app` が開く。移動・削除済みのパスでエラーが出る。
- [ ] `https` / `http` / `mailto` URL が既定アプリで開く。不正 URL は設定で検出する。
- [ ] 送信アクションで TextEdit に安全な組み合わせを送り、物理キーの解放まで送信を待つ。

- [ ] Fキーからアプリ・URL・入力ソース・キーの組み合わせを実行できる。自己再帰や同時実行がない。
