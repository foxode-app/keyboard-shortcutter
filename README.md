# Keyboard Shortcutter

Apple Silicon Mac 向けの、Swift / SwiftUI 製メニューバーアプリです。物理キーの操作とアクションをルールとして保存します。標準設定は **左 Alt（Option）単独押し → ABC 英字**、**右 Alt（Option）単独押し → ひらがな**です。どちらも変更・無効化・削除できます。専用の「Fキー」画面からF1〜F20の動作も変更できます。

## ダウンロード

[GitHub Releases の v1.1.7](https://github.com/foxode-app/keyboard-shortcutter/releases/tag/v1.1.7) から `Keyboard-Shortcutter-1.1.7-arm64.dmg` をダウンロードし、アプリを Applications にドラッグしてください。macOS 13以降・Apple Silicon向けのプレビュー版です。1.1.7では、右Optionでひらがなを選んでも前面アプリが英字のまま入力する場合の自動補正と、キー解放通知の欠落でOptionやFキーが反応しなくなる問題への対処（未公開の1.1.6の修正）を加えました。操作方法と権限設定は [Foxode の製品ページ](https://foxode.com/products/keyboard-shortcutter/) も参照してください。

Releases の DMG がインストール用ファイルです。GitHub が自動生成する「Source code」は、下記の手順でビルドするためのソースコードです。

## 必要環境

- **実行環境: macOS 13 Ventura 以降、Apple Silicon（M シリーズ / arm64）。**
- ビルド: **フル版 Xcode 16 以降**。Command Line Tools 単体では、検証環境の SwiftUI マクロプラグインと XCTest が不足するため、アプリのビルド・テストはできません。
- 開発環境: macOS 27.0.1、Swift 6.4、Xcode 27.0。Swift 言語モードは 5。最小対応 OS 上での実機検証は別途必要です。
- 外部ライブラリ、Homebrew、仮想 HID ドライバ、常駐デーモンは不要です。

## ビルドとインストール

```sh
git clone https://github.com/foxode-app/keyboard-shortcutter.git
cd keyboard-shortcutter
make test
make app
open "build/Keyboard Shortcutter.app"
```

`make app` は arm64 の Release 実行ファイルとアイコンを `build/Keyboard Shortcutter.app` に格納します。既定は開発用のアドホック署名です。`SIGNING_IDENTITY="Developer ID Application: …" make app` で、指定した署名 ID による Hardened Runtime・タイムスタンプ付きの配布用署名に切り替わります。公開前に別途公証とステープルが必要です。[直接配布の手順](docs/DIRECT_RELEASE.md) を参照してください。継続して利用する場合は、アプリを終了し、Finder で `/Applications` にコピーしてからそのコピーを開いてください。権限を付与する前に配置場所を決めておくと設定しやすくなります。

Xcode からは `KeyboardShortcutter.xcodeproj` を開き、`KeyboardShortcutter` スキームで Build / Run できます。ターミナルからの Xcode ビルドは次の通りです。

```sh
make xcode
open "build/xcode/Build/Products/Release/Keyboard Shortcutter.app"
```

すべての Make コマンドとビルドスクリプトは、指定済みの `DEVELOPER_DIR`、現在選択されているフル版 Xcode、`/Applications/Xcode.app` の順に開発環境を選びます。システム全体の `xcode-select` 設定は変更しません。別の場所の Xcode を使う場合は `DEVELOPER_DIR="/path/to/Xcode.app/Contents/Developer" make app` と指定できます。Swift Package のテストは `make test` で実行します。Xcode アプリ用スキームにはテストターゲットを含めていません。

## 初回設定と操作

Foxode からの直接配布を対象にしています。Mac App Store への配布を進める場合は [申請準備と機能の対応状況](docs/APP_STORE_RELEASE.md) を参照してください。App Sandbox は無効です。

1. メニューバーのキーボードアイコンから「設定を開く…」を選びます。
2. 入力監視の権限を付与し、案内に従ってアプリを再起動または監視を再開します。
   1.1.5以降、ひらがなを含む入力ソース選択自体にアクセシビリティは不要です。Fキーの割り当て・Optionの抑止・ショートカット送信などを使う場合は、別途アクセシビリティを許可してください。1.1.7では、許可されている場合に限り、ひらがなへの切り替えが前面アプリに反映されなかったときの自動補正にも使います。
3. 初期ルールの入力ソースを確認します。左 Option には ABC、右 Option には日本語の「ひらがな」を選びます。候補は実行時に取得し、利用可能な ABC とひらがなを優先して初期提案します。ひらがなを識別できない場合、右 Option の入力ソースは未設定になるため手動で選択してください。入力ソースの ID は固定していません。
4. テキストエディタで左 Option を単独で押して離すと英字、右 Option を単独で押して離すとひらがなになることを確認します。

「マッピングを追加」でルールを追加できます。トリガーは左右別の Option / Command / Control / Shift の単独押し、またはキーと修飾キーの組み合わせです。単独押しは離したときに判定し、押している間に別のキーやマウス操作をすると実行しません。長押しだけであれば単独押しとして扱います。通常のアクションはキーリピートで繰り返し実行しません。音量・画面の明るさのシステム操作は、長押しで繰り返し調整できます。

記録ボタンでショートカット入力欄にフォーカスを置き、組み合わせを押すと登録できます。単独修飾キーは一覧から左右を指定します。アクションは次の 5 種類です。

- **音量・再生・明るさ:** 音量を下げる／上げる、消音の切り替え、再生／一時停止、次の曲／前の曲、画面を暗くする／明るくする。
- **入力ソース選択:** システムの入力ソース一覧から選択。
- **アプリ起動:** ファイル選択ダイアログで `.app` を指定。
- **URL を開く:** `https`、`http`、`mailto` の URL を既定のアプリで開く。
- **ショートカット送信:** 指定したキー操作を前面のアプリへ送信。物理キーが離されるまで待ち、5 秒以内に離されなければ中止します。

メニューから監視の一時停止・再開、設定、終了を操作できます。「ログイン時に起動」は任意で有効化できます。macOS が承認を求める場合は「一般 → ログイン項目」で確認してください。

メニューバーのキーボードアイコンをクリックまたは右クリックして開くメニューと、設定画面の下部に **「開発者のサイト（Foxodeについて）」** があります。選択すると、既定のブラウザで [Keyboard Shortcutter の個別製品ページ](https://foxode.com/products/keyboard-shortcutter/) を開きます。設定画面では、どのタブを開いていてもリンクを選べます。

## Fキーに動作を割り当てる

1. 設定の **「Fキー」** タブを開き、F1〜F20の「割り当てる…」を押します。
2. 「音量・再生・明るさ」、アプリ起動、URL、入力ソース、ショートカット送信から動作を選び、保存します。Control / Option / Shift / Command / Fnとの組み合わせも登録できます。
3. アクセシビリティを許可し、監視を再開します。設定したFキーの元の動作を置き換えるために必要な権限です。

**「F9：音量− ／ F10：音量＋を追加」** で2件をまとめて登録できます。どちらかの裸のFキーが登録済みの場合は、既存の設定を上書きせず、各キーの「編集」で変更します。アップデートだけでプリセットが自動追加されることはありません。

有効なFキーの割り当てがある間は、そのキーの押下・リピート・解放をアプリが処理し、元のFキー操作を前面アプリへ渡しません。修飾キーが一致しない操作、未設定・無効なキー、競合するルールのキーは通常どおり届きます。一時停止・終了・キー記録中は割り当てを停止します。設定を切り替えるときは、キーを離してください。Fキー以外の既存ショートカットは、元の操作を遮断する機能の対象外です。

Apple製キーボードなどで最上段がメディアキーとして動く場合は、macOSの「キーボード → キーボードショートカット → ファンクションキー」で「F1、F2などのキーを標準のファンクションキーとして使用」を有効にしてください。他社製キーボードではFnロックなどの設定を使用する場合があります。Fnと併用して使う場合は、そのFnを含むトリガーを登録します。アプリはmacOSやキーボード本体の設定を自動変更しません。F13〜F20は対応キーのある機器で使用できます。

音量・明るさの動作はmacOSの標準メディアキー相当です。macOS側が音量を調整できない出力先や、明るさ調整に対応しない外部ディスプレイには使えません。メディア再生は対応するアプリが対象です。音量・明るさだけが長押しで繰り返され、消音・再生・アプリ起動・URLなどは1回の押下で1回実行します。

## Option（Alt）本来の動作を無効にする

設定のマッピング画面で **「Option（Alt）本来の動作を無効にする」** をオンにすると、監視中は左右の物理 Option を前面アプリへ修飾キーとして渡さなくなります。初期値はオフです。このモードではアクセシビリティを許可してください。通常モードの入力監視とは必要な権限が異なります。切り替える前に、押しているキーをすべて離してください。

- 左 Option 単独 → ABC 英字、右 Option 単独 → ひらがなのルールは引き続き動作します。
- Option + K は前面アプリには K として届きます。Option + 矢印や Option を使う特殊文字入力、クリック・スクロールの修飾にも Option を渡しません。Command / Control / Shift など他の修飾キーは維持します。
- このアプリのルール判定は元の物理キー操作を使うため、登録した Control + Option + K などのトリガーは引き続き利用できます。「ショートカット送信」で意図的に送る Option の組み合わせも維持します。
- 一時停止・終了・ショートカット記録中は抑止を停止し、通常の Option に戻ります。オフにすると通常の受動監視へ戻り、設定は再起動後も保持されます。

この機能は実行中のアプリのイベント監視により働きます。起動前・ログイン画面・Secure Keyboard Entry などの保護された入力、ハードウェア状態を直接読むアプリまで一律に無効化する機能ではありません。音量・輝度などの特殊メディアキーとの組み合わせも対象外になる場合があります。権限付きの実機動作は [確認手順](docs/MANUAL_TESTS.md) に沿って検証してください。

## 権限とプライバシー

有効なFキーの割り当てがなく、Option の動作も無効にしない場合は **受動的な `CGEventTap`（listen-only）** で入力イベントを観測します。元のキーイベントを削除・変更しないため、登録した組み合わせは前面のアプリや macOS にも届き、既存ショートカットと両方が動く場合があります。必要な「入力監視」権限は「システム設定 → プライバシーとセキュリティ → 入力監視」で付与してください。

Fキーを割り当てる場合、またはOption の動作を無効にする場合は **能動的な `CGEventTap`（defaultTap）** で、登録したFキー操作を抑止します。Option無効化を有効にした場合は、Optionの押下・解放イベントの抑止と他の入力からのOptionフラグの除去も行います。この書き換えに必要な権限は「アクセシビリティ」です。このモードでは入力監視を追加条件にしません。権限が足りない場合や監視を開始できない場合は開始失敗を表示し、無効化が動作中とは表示しません。[Apple のイベントタップ仕様](https://developer.apple.com/documentation/coregraphics/cgeventtapoptions) を参照してください。

「音量・再生・明るさ」「ショートカット送信」は合成入力を使うため、アクセシビリティが必要です。これらの機能を利用する場合に、設定画面から明示的に許可してください。1.1.5以降、Fキーの割り当てとOption抑止がなく、ひらがなを含む入力ソース切り替え・アプリ起動・URL起動だけであればアクセシビリティは不要です。ただし1.1.7では、許可がない場合はひらがな切り替えの自動補正を行いません。旧版1.1.3では、ひらがな切り替えにもアクセシビリティが必要でした。

入力ソース切り替えは、物理キーを離した後にmacOSの入力ソース選択APIを呼びます。キー解放待ちは最大5秒で、別の入力・前面アプリの変更・監視停止時は中止します。新しい入力ソースの指定は古い待機要求を取り消し、選択に失敗した場合はエラーを表示します。

1.1.7では、ABCなどの英字配列からAppleの日本語入力の「ひらがな」へ切り替えたときだけ、前面アプリが切り替えを反映したことをmacOSの入力ソース変更通知で確認します。0.15秒以内に確認できない場合は、英字配列を選び直してから「かな」キーを1回だけ送信し、前面アプリ自身に日本語入力を起動させます。すでに日本語が選択されている間は「かな」キーを送りません。以前の版の余分な文字・空白・入力履歴表示・警告音は、日本語選択中に届いた「かな」キーが原因でした。補正はアクセシビリティ許可時のみ行い、前面アプリの変更・保護された入力・修飾キーの押下・別の入力ソース指定・監視停止では中止します。カタカナ・英字モード、他社製の日本語入力、日本語以外の入力ソースは選択APIだけを使います。

入力された文字列は取得・記録・保存せず、判定に必要なキーコードと押下状態のみをメモリで扱います。ネットワーク通信、解析、テレメトリー、管理者権限の要求、シェルコマンド実行はありません。URL アクションやFoxodeのリンクで起動したブラウザなどは、通常どおり通信します。

## 設定ファイル

ルールは `~/Library/Application Support/KeyboardShortcutter/settings.json` にバージョン付き JSON として保存します。初期ルールは設定ファイルがない場合のみ作成します。既存設定をアップグレード時に初期化しません。システム操作はアクションの `systemAction` に保存します。項目がない従来のルールもそのまま読み込みます。Option の抑止設定は `disableOptionModifiers` として保存し、項目がない既存設定ではオフとして読み込みます。破損した設定や未対応のスキーマはエラーとして表示し、元ファイルを保持します。修復が必要な場合は、アプリ終了後にファイルをバックアップしてから編集してください。

正式な Bundle ID は `com.foxode.keyboardshortcutter.app` です。旧ローカル版（`local.keyboardshortcutter.app`）からは一時停止状態を、新版に設定がない場合のみ引き継ぎます。ルール・Option 抑止設定の JSON 保存先は変更しません。入力監視・アクセシビリティの許可は新しいアプリに対して再設定してください。旧版を終了してから入れ替え、「ログイン時に起動」は新版で有効にし直してください。

## 制限とトラブルシューティング

- **監視中なのにOptionなどが反応しなくなった:** キー解放通知の欠落で押下状態が残る場合があります。1.1.6以降（公開版は1.1.7から）は、入力が落ち着き、物理キーがすべて離れていることを確認して残った状態を自動解除します。改善しない場合は「権限と起動 → 状態を再確認」で監視を再作成し、反応しないキー・使用アプリ・入力メニューの表示だけは変わるかを記録してください。保護された入力中は解除判定を行いません。
- **監視を開始できない:** 通常モードでは入力監視、Fキー割り当て・Option抑止モードではアクセシビリティがオンかを確認してください。許可したアプリと起動したアプリが同じ場所かも確認し、アプリを再起動します。アドホック署名は再ビルドにより変わるため、権限一覧で削除・追加が必要な場合があります。
- **Fキーが反応しない:** 「Fキー」画面の動作状態とアクセシビリティを確認してください。再生・音量キーとして入力されている場合は、標準のFキーとして使う設定またはFnを含む登録が必要です。同じトリガーの競合も確認してください。
- **Option が無効にならない:** 設定のチェック、監視中の表示、アクセシビリティ権限を確認してください。一時停止・キー記録を終了し、すべてのキーを離してから TextEdit で確認します。権限変更後は再起動が必要な場合があります。監視エラーが表示される間は抑止できません。
- **一部のアプリで反応しない:** パスワード欄や Secure Keyboard Entry などではイベントを取得できないことがあります。TextEdit など通常の入力欄でも確認してください。
- **切り替わらない:** macOS の「キーボード → テキスト入力」で入力ソースを追加し、アプリ内の一覧を更新して選び直してください。入力方式の変換状態やアプリごとの入力ソース設定も影響します。
- **表示だけが切り替わる:** macOSの入力ソース選択APIだけでは、前面アプリが日本語入力を起動せず、メニューバーが「あ」でも英字が入力される場合があります。1.1.7は英字配列→ひらがなの切り替えでこれを検知し、自動で補正します。アクセシビリティ未許可の場合、補正の前後に別の操作をした場合、メニューなど別の方法で切り替えた場合は残ることがあります。その場合は左Option→右Optionの順に押すか、入力欄へフォーカスを戻してください。補正の記録は `/usr/bin/log show --last 1h --predicate 'subsystem == "com.foxode.keyboardshortcutter.app"'` で確認できます（入力文字は記録しません）。
- **競合の警告:** 同じトリガーを持つ有効なルールが複数あると、どれも実行しません。片方を無効化するかトリガーを変更してください。macOS や他アプリのショートカット競合は自動検出できません。
- **キーの表示と刻印が違う:** キーコードは物理位置に対応し、文字ラベルは主に ANSI 配列です。JIS / ISO や非英語配列では記録機能と実機確認を併用してください。
- **Caps Lock:** 通常の flagsChanged はロック状態を表し、物理的な離した瞬間を確実に取得できないため、単独押しトリガーは提供しません。
- **ログイン時に起動しない:** `/Applications` のアプリで有効化し、macOS のログイン項目の承認を確認してください。

```sh
make icon                  # AppKit のソースから .icns を再生成
make build                 # Debug ビルド
make test                  # 判定・保存・検証、および権限不要のmacOS統合テスト
./scripts/swift-env.sh xcrun swift test --filter TriggerMatcherTests
make format                # Swift 標準 formatter で整形（利用可能なツールチェーン）
make lint                  # 同じ規約を検査
```

Swift は 4 スペース、型は UpperCamelCase、メソッド・変数は lowerCamelCase を使用します。外部依存がないため依存関係ロックファイルは生成されません。変更時は `make test`、`make lint`、`make app` を実行してください。コミットは簡潔な命令形で、PR には目的・検証結果と UI 変更のスクリーンショットを含めます。

アプリは Apple のシステムフレームワークを使用し、第三者のソースコード・ライブラリ・フォントを同梱していません。アプリアイコンは `scripts/create-icon.swift` の図形描画から生成しています。API キー、署名証明書、秘密鍵、個人の設定、ビルド出力はコミットしないでください。

設計と拡張手順は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)、実機確認は [docs/MANUAL_TESTS.md](docs/MANUAL_TESTS.md) を参照してください。ユニットテストだけでは、権限付きのグローバル入力動作を検証できません。

## 1.1.7の修正と検証結果（2026-10-20）

1.1.6で、英字から右Optionで日本語へ切り替えると一度で切り替わらないことが多く、左Option→右Optionと押し直すと切り替わる、との報告がありました。

macOS 27.0.1 / Apple Silicon / ANSI配列 / Apple日本語入力で、テスト用のAppKit入力欄と一時プロファイルのChromeを使って再現しました。入力ソース選択APIだけで切り替えた後に `aiu` を自動入力すると、メニューとOSの選択状態は「ひらがな」なのに英字のまま入力される場合があります。

- 英字入力直後の単独切り替えは、AppKitで33回中2回（実際のアプリ経由8回中1回を含む）失敗しました。Chromeでは57回中0回でした。
- 英字へ戻した0.2秒後にひらがなを選ぶと、AppKitで10回中4回、Chromeで11回中3回失敗しました。英字とひらがなを続けて選ぶと、AppKitで16回中14回、Chromeで6回中6回失敗しました。
- 失敗時は、このアプリ自身の選択による入力ソース変更通知が1回しか届きません。成功時は前面アプリと日本語入力からの通知が続けて届き、入力欄にフォーカスがある場合は2回目が40ms以内でした。

この通知で反映を確認し、確認できない場合だけ英字配列を選び直してから「かな」キーを送る補正を加えました（「権限とプライバシー」参照）。次の方式は採用していません。

- 「かな」キーだけで切り替える方式は、切り替えの失敗はありませんでした。ただし、Chromeで約150回中6回、直前の英字の前に空白が入りました（`xy` → `x y`）。
- 選択API直後に「かな」キーを送る旧方式（1.1.2〜1.1.4）では、反映失敗時に「かな」キーが文字として届き、AppKitの入力欄に制御文字U+0010が入りました。日本語選択中に送ると、Chromeで直前の文字が再変換される、空白が入るなどの影響がありました。

検証結果は次のとおりです。

- `make test`: 146件成功（純粋ロジック51件、macOS統合95件）。補正の実行、反映確認時の無動作、対象外の入力ソース、各中止条件、連続押下、英字指定によるキャンセルを検証しました。
- `make lint`、Developer ID署名付き `make app`、署名検証が成功しました。1.1.6を `build/ime-activation-backup-20261020/` にバックアップし、`/Applications` に1.1.7（ビルド9）を適用しました。設定ファイルのハッシュ一致と、macOS側のイベントタップが有効であることを確認しました。
- 補正の単体検証では、意図的に作った反映失敗状態からAppKit・Chromeとも10回中10回で「あいう」に復帰しました。自然に起きた失敗10件も検知し、全件で補正に成功しました。入力欄にフォーカスがない状態で補正を強制しても、警告音の経路に入らず、余分な文字も入りませんでした（各5回）。
- 1.1.7本体経由で、右Option単独と、左Option→0.15秒・0.25秒後に右Optionを自動操作しました。AppKit・Chromeとも24回中24回で「あいう」になり、そのうち2回で自動補正が働きました。
- 配布用アプリとDMGのApple公証が成功。Developer ID署名、公証チケット、Gatekeeper検証済みのDMGをGitHub Releasesで配布します。配布用アプリの実行ファイルは、このソースのReleaseビルドと署名部分を除いて同一であることを確認しました。1.1.6は単独では公開せず、その修正は1.1.7に含めています。

制限事項です。

- 補正時は一瞬「A」に戻ってから「あ」になります。補正が働いたときに限り、Chrome系アプリで直前の英字の前に空白が入る可能性が残ります。補正しない通常の切り替えでは「かな」キーを送りません。
- 入力欄にフォーカスがない画面では通知が遅れて届くため、補正が働くことがあります。この場合の文字入力への影響は確認されていません。
- 通知の数による判定はmacOS 27.0.1で確認したものです。Codexでの実操作、他のmacOS・日本語入力・キーボード配列は未確認です。利用者の実操作で症状が解消したかも未確認です。
